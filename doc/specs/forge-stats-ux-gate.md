# forge-stats UX 閘門

每次修改 forge-stats 在畫面上呈現的內容，都要先通過這道閘門才能上線。改動範圍包括 pane、band、頁籤、鍵位、配色，以及高度規則。

依據：
- PM 01M7KRP3（2026-11-17，origin=operator）。
- PM 01M7KS6H：門檻與 ThinkSmart 的 UX 總監閘門相同。ThinkSmart 是觸控版，評分項目各自寫；本表是終端機版，項目以 autopilot `docs/guide/tux-guidelines.md` v1.4 為底。

只改內部、畫面輸出逐字元不變的修改（重構、純測試）不需要過這道閘門。

## 誰評、怎麼算過

- 評審共兩家，都用最高檔：`gemini-4-carbon-high`（agy）與 `gpt-6-astra`（codex）。兩家各自獨立評，不互看結果。
- **通過條件**：兩家都給 **≥ 8/10**，且兩家都**沒有 Critical**。
- **最多 3 輪**。第 3 輪還沒過就停手，把兩家的報告交給 PM 裁決，不開第 4 輪。
- 評審意見只是主張，不是定論。實作者可以舉證反駁，例如證明那個情境根本不會發生、或是截圖讀錯了；反駁內容要寫進下一輪的評審包。
- 每一輪的評審包都要包含：
  - 這次 diff 的 base..head；
  - 下面「必交截圖」全部；
  - 上一輪的發現，以及實作者的回應。
- 結果存放在 `doc/design/ux-gate/<主題>/`（例如 `pane-batch2/`），每一輪（`r<n>`）有 `r<n>-astra.json`、`r<n>-carbon.json`（兩家的原始 JSON 和分數）、`r<n>-packet.md`、`r<n>-dispositions.md`、`r<n>-keyprobe.log`，另有總表 `verdicts.md`。
- 上線前先給 PM 看 160x40 截圖，PM 放行才能上線。

## 必交截圖

截圖用測試 harness 輸出成純文字，從假資料直接畫出來；每段文字附上它的語意色名，並在淺色、深色兩種主題下各解析一次。資料用固定的假資料，主機名一律用 `host-a` 這類假名。

| 代號 | 終端 | 資料 | 用來抓的失敗 |
|---|---|---|---|
| S1 | 160x40（淺色、深色各一） | 滿量：待決 3、卡住 6、離線 2、12 個池、交辦 3 | 內容超過高度上限時，捲動區錯位，或底部操作列被擠掉 |
| S2 | 120x30 | 同 S1 | 中等寬度下欄位互相擠壓、截斷之後失去辨識度 |
| S3 | 80x24 | 同 S1 | 窄終端下 CJK 對齊崩掉、整列折行 |
| S4 | 160x40 | 少量：0 卡住、1 交辦、3 個池 | 內容少時仍然補空白列，pane 沒有變矮 |
| S5 | 160x40 | brief 檔不存在；另一份是 brief 超過 5 分鐘沒更新 | 缺資料時畫面空白，或把舊資料當成新資料顯示 |
| S6 | 160x40 | Pet 次頁 | 次頁重複出現總覽已經有的東西，或預設頁跑到 Pet |

## 評分項目

兩組項目合起來打一個總分（1–10），「好用」組權重較高：好用組有任何 Major 以上的發現，總分不得高於 7。每項寫它防的失敗。

### (a) 好用

1. **重要的事第一眼看到**：待決數與最舊一張標題、卡住的線、快用完的池，在 S1–S3 都不用捲動或切頁就看得到，且排在最上面。防：卡住的線排在第二頁，操作員沒看到。
2. **同一件事只出現一次**：一條線、一張卡、一個池在預設頁只出現在一處。防：同一張卡同時列在「待決」和「卡住」，操作員以為是兩件事。
3. **高度依內容**：總高度 ≤ `min(maxRows, floor(rows*0.6))`（TUX v1.4），沒有整列空白補位。防：內容 5 列卻佔 25 列，把對話擠走（11-17 操作員原樣抱怨）。
4. **80／120／160 欄都不截壞、不錯位**：CJK 依顯示寬度（2 格）算，超長標題以「…」截斷，欄位不錯位、不折行。防：80 欄時中文標題把用量欄推出畫面。
5. **按鍵在最底下、靠近輸入框**：鍵位提示固定在 pane 底部（緊貼輸入框），頂部狀態帶每一項都對到一個鍵；「待決」一鍵跳到 autopilot pane。防：看到「待決 3」卻不知道按什麼去處理。
6. **全中文**：畫面上的標籤、狀態、提示全部正體中文（帳號名、model 名、指令名等專有名詞除外）。防：英中混雜的標籤讓操作員停下來翻譯。
7. **格子少**：預設頁就是一頁；頁籤 ≤ 2（總覽 + Pet）；不加框。防：資訊切成三頁，每頁只有幾列（操作員原話「切分太多格」）。
8. **資料誠實**：數字取自 `fleet.brief/1`、`codeforge.fleet-quota/1` 原檔，不另算；過舊標年紀；缺資料說缺什麼。防：brief 已停更 1 小時，畫面仍顯示「0 卡住」。
14. **用順手的操作順序不准擅改**：操作員已經用慣的操作順序，例如待決卡答題區的「背景→卡住→選項→建議→補充」，或按鍵、按鈕的位置，沒有先問過操作員就不准改。版面規則也不能當改順序的理由：貼底指的是整個答題區要靠近輸入框，不是把答題區裡面的順序倒過來。評審發現順序跟上一版不同，又沒有操作員確認的紀錄，一律判 Major。來源：PM 01M7PCAA（操作員 11-18 原話：「你舊的 pane 幹嘛把選項跟補充欄位對調啊? 因為 bottom up 改道嗎? 這樣很不順手耶」）。防：cf9f25bee 為了貼底，把選項移到補充欄位下面，操作員每次答題都按錯位置。

### (b) fancy

9. **層次**：一眼分得出區塊（待決／卡住／池／交辦）與區內主次（主體 vs 次要說明），靠縮排、粗細與顏色，不靠框。防：所有列同一個重量，眼睛找不到起點。
10. **配色**：只有要操作員處理的用 warning，卡住／離線用 error，可按的用 merged，閱讀文字用 inactive；**淺色與深色終端機都要測**（S1 各交一張淺、深）。防：深色主題下 inactive 灰在淺色主題幾乎看不見；滿畫面紅黃，真正要處理的那項不突出。
11. **對齊**：同一區的欄位起點一致，數字靠右，bar 長度一致。防：用量 bar 長短不一，讀成用量差異。
12. **留白**：區與區之間至多一列空行，且只在有內容的區之間；不留裝飾性空白。防：留白吃掉 60% 上限內的內容列。
13. **整體質感**：與 autopilot pane 同一套視覺語言（Fable r4b：左標籤欄 + 一條垂直線、單列狀態帶），放在一起不像兩個產品。防：兩個 pane 並排時風格衝突。

## 嚴重度

- **Critical**（有一項就不過）：
  - 違反第 3 項的高度上限，或有整列空白補位；
  - 畫面上的標籤、狀態或提示出現簡體字；
  - 操作員需要處理的項目在 S1–S3 任一張截圖裡看不到；
  - 同一項目在預設頁出現兩次；
  - 顯示的數字與來源檔案不一致；
  - 缺資料或資料過舊時，畫面看起來像正常狀態；
  - 預設頁不是總覽。
- **Major**：會讓操作員多花一步，或讀錯一次。例如欄位錯位、截斷後兩列無法區分、配色語意錯了。
- **Minor**：措辭、間距、順序上的偏好。

發現一律要附一個做得到的情境：在哪一張截圖、哪一列，會讓操作員看錯或做錯什麼。沒有情境的意見只算備註，不影響分數。
