# ux-v5 設計 brief：以 V1 為底的「選單＋視窗」

## 操作員要什麼（d-cc464346）
上一輪選了 V1（框線面板），但補充原話：「還是不太好，想辦法畫選單跟視窗？你後來有 survey 成功案例嗎」。
他要的是真的「選單＋視窗」介面：
- 上方有**選單列**，選單項可以**展開下拉**；
- 內容放在**有標題的視窗**裡；
- 答題用**對話框式的小視窗**；
- 不要只是兩欄清單。

## 硬限制（照舊；被擋住的做法要寫清楚是哪條擋的，不要默默放棄）
1. （**更正 2026-11-06：這條的「沒有疊層」是錯的**，`Box position="absolute"` 可以真的疊，PM 已裁定可用，規範見 tui-guideline §14.1。原文保留如下。）畫在 Claude Code mod 的 AbovePrompt band：元素是 Box/Text/Button/Input 等，**沒有自由定位、沒有疊層**。下拉和對話框只能「重畫 band 的一塊」來假裝；陰影、背景變暗、蓋住下層做不到。
2. 高度最多**半個畫面**（含輸入框）；寬度扣掉右邊保留給 `[-]` 的 5 格。
3. Button hotkey 只能是**一個數字或一個小寫字母**；輸入框空著時打數字會直接按下 band 的按鈕。Alt/F 鍵/Ctrl/大寫都不行；`?` 被 Claude Code 自己用掉。
4. **數字直接選**：答題時按數字就選好並換下一張（連答節奏照 v4）。
5. **焦點穩定**：焦點跟著 Button 的 key 走；焦點所在的元素消失時跳到第一個 Button；autoFocus 只在剛拿到鍵盤時生效。換卡、開關下拉／對話框時，反白不能亂跳。
6. 截圖不能有真實金額或個人資料（`$` 金額、`acct-` 別名）。

## 每個變體要交的畫面（每個 120x44 一張，另加 80 欄一張）
1. **主選單**：還沒開始答，8 張待決卡（用 v4 的假資料）。
2. **下拉展開**：選單列上某一項展開的樣子。
3. **答題對話框**：第 1、2 張已選，停在第 3 張，對話框式小視窗。
4. **送出後**：前 3 張已送出，停在第 4 張。
5. **80 欄**：答題對話框那個狀態，終端 80 欄。

## 每個變體要寫的
- 三行說明：借了什麼（指名 survey 的哪個案例、哪張圖）、好在哪、代價。
- 被限制擋掉的做法清單：做法 → 擋住它的限制編號 → 改用什麼。
