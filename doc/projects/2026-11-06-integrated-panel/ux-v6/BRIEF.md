# ux-v6 設計 brief：固定四區（選單列／左側子選單／主視窗／下方固定快速操作）

## 操作員要什麼（d-03a7425f）
上一輪選了 G2（三視窗），補充原話：「我的想法跟三窗比較像，但是是上面是選單，左側式子選單，下方是固定快速操作；你畫成 dialog 會不會操作有我講的問題是線、注意力、游標都要跳來跳去?」

PM 的理解（固定四區、不浮動）：
- **上方：選單列。**
- **左側：子選單**＝目前選到的選單項目底下的項目清單。
- **中間：主視窗。** 答題就在這裡原地進行，不另外彈出對話框。
- **下方：固定的快速操作列**，數字鍵／快捷鍵的位置永遠不變。

如果你認為 PM 對「左側子選單」或「下方固定快速操作」理解錯了，照你的理解做，並在 design.md 開頭寫出你的理解和理由。

## 要求
1. **不用浮動 dialog、不用疊層。** 答一張卡的過程中，視線、注意力、游標（反白）最好都留在同一個區域。
2. **量測並寫出「答一張卡時的移動次數」**，方法固定如下（兩個變體用同一套，才比得了）：
   - 起點：答題畫面，停在第 3 張，反白在第一個選項。
   - 一次「答一張」= 讀題目 → 讀選項 → 按數字選定 → 看到下一張出現。
   - 數三個數字：
     - **視線換區次數**：視線離開目前所在區域、到另一個區域（選單列／子選單／主視窗／快速操作列／輸入框）的次數；
     - **反白換區次數**：反白（焦點）跨區移動的次數；
     - **畫面跳動**：按下數字後，題目、選項、反白這三樣有沒有任何一樣換了螢幕位置（列號或欄號），有幾樣。
   - 每個數字都寫出是在哪一步發生的。在真機上照做一次，量到的和設計預期不同時，以真機為準並註明。
3. **五個畫面，真機截圖**（120x44，80 欄另一張）：
   1. 主選單：還沒開始答，8 張待決（沿用 v4 的假資料）。
   2. 子選單：選單列切到另一項（例如「圓桌」或「用量」）時，左側子選單換成那一項的內容。
   3. 答題：第 1、2 張已選，停在第 3 張。
   4. 送出後：前 3 張已送出，停在第 4 張。
   5. 80 欄：答題畫面，終端 80 欄。

## 硬限制
1. 畫在 Claude Code mod 的 AbovePrompt band：Box/Text/Button/Input 等元件。這一輪**不用疊層**（`position: "absolute"`）。
2. 高度最多半個畫面（含輸入框）；寬度扣掉右邊保留給 `[-]` 的 5 格。
3. Button hotkey 只能是一個數字或一個小寫字母；輸入框空著時打數字會直接按下 band 的按鈕；字母熱鍵要先拿到鍵盤。Alt／F 鍵／Ctrl／大寫都不行；`?` 被 Claude Code 自己用掉。
4. 數字直接選：答題時按數字就選好並換下一張。
5. 焦點穩定：照 tui-guideline §14.2（焦點跟著 Button key 走；反白所在的 Button 消失時落點不固定，所以不要讓它消失而沒有接手的按鈕）。
6. 截圖不能有真實金額或個人資料（`$` 金額、`acct-` 別名）。
