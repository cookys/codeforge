## 2.5 Global Constraints (copied verbatim into every dispatch)

- pet.json schema name stays exactly `codeforge.pet-view/1`; the sprite is a new OPTIONAL field `village.sprite`, JSON `null` when the village has no sprite. No other existing field changes name, type or meaning.
- Sprite shape: `width` 24, `height` 24 (height MUST be even), `transparent` is the single ASCII char `.`, `palette` maps single ASCII chars to `[r,g,b]`, every r/g/b ∈ {0,95,135,175,215,255} (xterm-256 cube), `frames` is an array of ≥ 2 frames, each frame exactly `height` strings of exactly `width` chars, each char either `transparent` or a palette key; `frame_ms` 500.
- Half-block mapping (one Raster cell = pixel rows 2y and 2y+1): both opaque → U+2580 `▀`, fg = top colour, bg = bottom colour; top opaque + bottom transparent → U+2580, fg = top, bg = 0x01000000; top transparent + bottom opaque → U+2584 `▄`, fg = bottom, bg = 0x01000000; both transparent → U+0020, fg = bg = 0x01000000.
- Raster `cells` = standard padded base64 of `columns*rows` little-endian u32 triplets `[codePoint, fg 0x00RRGGBB, bg]`, row-major; `columns` = width, `rows` = height/2. Encode as `new Uint8Array(u32.buffer).toBase64()` (the form the engine's `RasterProps` example uses); the same string feeds both `<Raster cells>` and `$.ui.blit({ cells })`.
- `codeforge statusline` must never fail, block, or change its printed text because of the sprite; `pet::view::publish` stays best-effort (one stderr line on failure).
- Mod code: every `$` call is written at the call site with literal arguments (e.g. `$.env.get('HOME')`, `$.clock.every(500, …)` — never a variable, `??`, or `sprite.frame_ms` as the interval); the mod never spawns processes (`$.process.*` not used); animation ≤ 4 frames per second; skip `$.ui.blit` when the next cells equal the current ones.
- Reader tolerance: in the mod, a missing `sprite` key, JSON `null`, or a sprite that fails validation (including `frame_ms !== 500`) all mean `sprite = null` → draw ASCII; the snapshot status stays `ok` when the pet/village fields are valid. `view.rs` always writes the `sprite` key (object or `null`) for a record that has a village.
- Formatting only through `./scripts/fmt.sh`; never bare `cargo fmt`.

## 2.6 Change-policy decisions

- **Compatibility impact**: `published-compatible` — `pet.json` gains an optional field; the only consumer is
  forge-stats (updated in this plan); readers that ignore unknown fields are unaffected. No migration.
- **Dependency decision**: `none` — Rust uses existing `serde_json`; the mod uses the engine's `btoa` and
  typed arrays. No new crates or packages.

## 4. Phases

### P1 — codeforge sprite 資料與契約（M）
1. 新增 `src/pet/sprite.rs`：
   ```rust
   pub struct Sprite { pub width: u32, pub height: u32, pub transparent: char,
       pub palette: &'static [(char, [u8; 3])], pub frames: &'static [&'static [&'static str]], pub frame_ms: u32 }
   pub static FERRIS: Sprite = Sprite { width: 24, height: 24, transparent: '.', palette: &[('o',[215,95,0]),('h',[255,135,0]),('d',[175,95,0]),('w',[255,255,255]),('k',[0,0,0])], frames: &[IDLE, BLINK], frame_ms: 500 };
   pub fn for_village(id: &str) -> Option<&'static Sprite> { match id { "rust" => Some(&FERRIS), _ => None } }
   pub fn validate(s: &Sprite) -> Result<(), String>  // 檢查 §2.5 全部規則
   ```
   `IDLE` / `BLINK` 每幀 24 個 `&str` 字面字串，內容取自 `.codeforge/research/pixel-pet/ferris-draft.json`
   的 `idle`、`blink`（owner 已在選項頁看過）。
2. 測試（先寫、先紅）：`validate(&FERRIS)` 為 Ok；故意壞的 sprite（奇數 height、列長錯、未知字元、非 cube
   色、單幀）各自回 Err；`for_village("rust")` 為 Some、其他四村 None。
3. `view.rs::build()`：village 物件加 `"sprite": sprite_json(v.id)`（`null` 或
   `{width,height,transparent,palette:{c:[r,g,b]},frames:[[..]],frame_ms}`）。測試：rust 有 sprite 且
   `frames.len()==2`、`height` 偶數；python 為 null；無寵物時 `village` 仍是 null。
4. README schema 段、CHANGELOG。
- **Acceptance**：`cargo test` 全綠（新測試在 base 上紅：`sprite` 模組不存在 → 以契約欄位斷言失敗為紅，
  不以編譯錯算紅——紅綠驗證改用 `view.rs` 測試：base 上 `v["village"]["sprite"]` 為 `Null` 時斷言失敗）；
  clippy、fmt、doc-drift 綠；`echo '{}' | codeforge statusline` 後 `pet.json` 的
  `village.sprite.width/height/len(frames)` = `24 24 2`。

### P2 — mod 畫 Raster 與待機動畫（M）
1. `types/index.d.ts` 加 `SpriteData`；`VillageData.sprite: SpriteData | null`。幀索引與上次送出的 cells 放模組變數
   （`session.start` 歸零），**不**用 `$.state` atom：寫 state 會讓整個 pane 每秒重畫兩次，而 `$.ui.blit` 就是為了不重畫
   （code review G2 後改定）。
2. `model.ts`：`parseSprite(raw)`（依 §2.5 驗證，含 `frame_ms === 500`；任何不符 → `null`，面板退回 ASCII；缺鍵也是 `null`，快照 status 不變）；
   `halfBlockCells(sprite, i)` 依 §2.5 半格對應填 `Uint32Array`，再 `new Uint8Array(u32.buffer).toBase64()`。
3. `register.tsx` 寵物區：`view.village.sprite` 非 null → `<Raster key="pet-sprite" columns={w} rows={h/2}
   cells={halfBlockCells(sprite, frame)} />`，名字／XP／屬性放 Raster 右側或下方（依 `bodyColumns`：
   ≥ 24+2+28 欄並排，否則上下）；null → 原 ASCII 畫法。Raster 只在 terminal surface 有，其他 surface 退 ASCII。
4. `session.start` 起 `$.clock.every(500, …)`（字面值，與既有 `$.clock.every(15_000, …)` 並列）：讀 pet atom，算下一幀 cells，與上一次 blit 的 cells
   相同就跳過，否則 `$.ui.blit({ requestId: 'forge-stats', key: 'pet-sprite', cells })`；blit 回 `deny`（沒掛載）
   就忽略。
5. 測試（用 `atob` 解回 little-endian u32）：(a) 解碼 cells：`columns=24 rows=12`、codePoint 集合 ⊆ {0x2580,0x2584,0x20}、含 0x2580；
   (b) 某一格依 §2.5 對應的 fg/bg 正確（取 Ferris 已知像素）；(c) sprite 為 null 的快照畫 ASCII、找不到
   Raster；(c2) 既有沒有 `sprite` 鍵的快照（現行 SNAP）status 仍為 ok 並畫 ASCII；(d) 推進時鐘一個 `frame_ms`，blit 被呼叫且 cells ≠ 初始幀；(e) 既有 6 個測試保持綠。
- **Acceptance**：`claude plugin test` 全綠、`tsc -p <mod>` 0、`claude plugin validate` 通過且 calls 不含
  `$.process.*`。

## 6. Risks + inversion

| 什麼會保證失敗 | 對策 |
|---|---|
| 半格對應寫反（fg/bg 顛倒）→ 顏色錯位 | §2.5 寫死對應；測試 (b) 釘一個已知像素的 fg/bg |
| sprite 字串長度錯一格 → 畫面歪 | Rust `validate()` + 測試；mod `parseSprite` 再驗一次，錯就退 ASCII |
| 計時器每次都 blit → 浪費、閃爍 | cells 相同就跳過；2 fps |
| WT 被降到 256 色 → 色偏 | 調色盤限 xterm-256 cube（§2.5） |
| pane 窄於 24 欄 → Raster 被裁 | Raster 由 site 裁切；窄時改上下排；記錄於文件 |
| statusline 因 sprite 變慢或出錯 | sprite 是 static 資料；序列化約 1.3 KB；publish 失敗只寫 stderr |
| 熱重載後計時器沒了 | `session.start` 重跑會重起計時器（reload 會重跑 `session.start`） |
