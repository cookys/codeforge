# Rubric — pane tabs r2 (7 autopilot-live tabs + console 5 → one set, quota tab)

> Source plan: doc/plans/2026-11-18-pane-tabs-r2.md (+ .mockups.md / .mockups.py), codeforge, PM 01M7N307 with hard rules PM 01M7N33J and PM 01M7N3FC. Builds on frozen plan 1fba336 (shared-tui-components). Frozen before generation 1.

R1: One system — every one of the 8 old pane tabs (incl. `?`) and 5 console tabs is mapped to exactly one new tab or retired with a named batch; no state leaves two tab strips or two entry points for the same content; console mode no longer swaps the strip.
R2: No transition artefacts — no standalone "open panel" row, no `›` next-tab button, no per-tab "open" buttons in the band; opening/closing/switching is one documented key scheme with no key meaning two things on any tab (the decide-tab hotkeys included).
R3: Fixed height — band is a fixed row count and pane total rows equal H in every listed state (empty, typical, overflow, stale, no_source, decide undo hold, fold open/closed, console mode on/off) at 160x40, 120x30 and 80x24; actionables sit in a reserved bottom zone next to the strip; the mockups demonstrably obey this.
R4: Red proof — the plan names a golden and a lint that fail on the current build (faa6b4cb6) for a concrete state (open row / growing bar) and says where that red output is recorded before the golden is switched to the new layout.
R5: Data from the bus — fleet-wide data comes only from `fleet console --json` (fallback console.json snapshot, console/1 only) and quota only from the bus (seats --quota / console quota items); every reporter file and old read path being retired is listed; session-local data is distinguished and justified.
R6: Stale is red with a reason — every failure mode (section stale, no_source, command fail with stale fallback, dropped items, per-seat/per-pool quota stale >10 min) has a trigger field, a broken-role rendering and reason text; a stale number is never shown without its mark.
R7: Quota tab — one row per pool with 7d%, 5h%, Taipei reset, 3-hour rate, projection at reset and verdict (red early-exhaustion "約 X 小時前用完", yellow >10% unused "約剩 Y%", green 90–95%); rate and projection come from capacity pace, never recomputed in the pane; the band shows only the most dangerous pool; the gap 95–100% and the no-pace-yet state are handled explicitly.
R8: Mockups — each of the 8 tabs has expanded mockups at 160x40 and 80x24 plus at least one state variant proving equal rows; content is plausible against the real console/1 and seats --quota shapes.
R9: Delivery — batches, owners, dates and dependencies are concrete (batch 1 = 待決, 艦隊, 現況, 額度 by 11-18 18:00 Taipei; no pin on 11-19 daytime); external dependencies (fleet/capacity quota_forecast, autopilot key table) say what ships if they slip; UX gate adds "畫面不跳動" and "沒有過渡產物" with checkable evidence; every live step carries real operator-pane screenshots.
