## 1. 目標

- **Used-by**：操作員在 pane 下半部就能完成所有選擇（換卡、選 a/b/c、寫附註、預覽、送出），上半部只剩不可點的標籤和資訊。
- **成功條件**（每條都有門檻和驗法）：
  1. R1 機械檢查：所有頁（`PAGES` 加 `EXTRA_PAGES`）在 docked 與 boxed 兩種模式、80x24／120x40／200x50 三種尺寸，以及 boxed 的宿主實際框高 5／13／17 列下，上半部可點元素＝0；`upper-clickables.test.ts` 的 `KNOWN` 清單清空。驗法：`bash mods/live/run-tests.sh`，看這幾條測試是綠的，而且反向探針是紅的（第 5 節）。
  2. 下半部完整：每種尺寸和模式下，待決頁的控制列都至少放得下「選項」和「送出」，換卡、附註可以用鍵盤或點擊在下半部完成。驗法：新增測試 `R1-lower`，斷言每種尺寸下 `key:a`、`key:s`、換卡鍵都出現在下半部的列裡。
  3. R5：`grid-check`（CJK 寬度 2、框線對齊）與 `contrast.test.js`（深淺雙主題）在新版面全綠。驗法：同上全套。
  4. R6：`pickKeys` 測試維持綠；新增的單列選項（第 3.3 節 L3、L4）照字母對應，按 a 一定選 A。
  5. 三種尺寸的真終端截圖（200x50／120x40／80x24，docked 與 boxed 各一，待決頁加 forge 頁），和本計畫第 4 節的 mock 逐張並排，附差異清單。
  6. 全套測試的失敗數不超過基線（AP develop 6db7e47ea：10 條，都是 speed tab）。
- **範圍**：autopilot `mods/live` 的 frame（上下半部的配置）、待決頁（docked 的 v7.4 S3、boxed 的 C 雙欄、D、緊湊清單）、band 與 Pane 共用的選取狀態、R1 檢查本身；codeforge `plugins/forge-stats` 的獨立 Pane 退役。
- **不在範圍**：band 單列排版本身（11-23 計畫已定、已上線，R3 只做核對）；資料來源（feeds、fleet CLI）；新增頁面；配色 token 改值（只用 R5 腳本驗）。

## 3. 設計

### 3.1 一條 frame 層的規則（所有頁共用）

頁面輸出改成兩區，由 frame 統一擺放：

- **控制區**（`controls`，就是現在的 `actions` 加上從 `body` 搬下來的可點列）：貼著下框線往上疊，永遠在下半部。所有帶 `press` 的 seg 只能出現在這裡和下框線（頁籤、鍵位提示）。
- **資訊區**（`info`，就是現在的 `body` 去掉可點列）：放在控制區正上方，往上長。空間不夠時從資訊區**最上面**開始截，最後一列換成「↑ 上面還有 N 列」，所以靠近控制區的內容（目前這張卡的重點）最後才被截掉。資訊區不放任何 `press`。

上下半的分界照現有檢查的定義：框高 H 列（含上下框線）時，第 0 到 ⌊H/2⌋−1 列算上半部。所以控制區最多可以用 ⌈H/2⌉−1 列（扣掉下框線）。這個上限叫 `ctrlCap(H)`，由 frame 算好放進 ctx，頁面不能自己算。

**H 用實際畫出的列數算，不用 maxRows**（g1 4c573674）：框會依內容縮高，所以 frame 先算出控制區要幾列，再算 H。如果資訊區比控制區短，frame 在資訊區頂端補空白列，讓資訊區列數 ≥ 控制區列數；這樣控制區一定落在下半部。補的空白列不帶 `press`。

**任何頁的控制區超過 `ctrlCap` 時**（g1 4c573674 第 3 點）：有退化階梯的頁（目前只有待決頁）由頁面依 `ctrlCap` 選階；沒有階梯的頁，frame 只保留控制區最下面 `ctrlCap − 1` 列，其餘收成一列「… 另 N 項 · ? 看鍵位」（這一列本身也在下半部）。兩種情況都有測試，H＝5（ctrlCap＝2）時對所有頁跑一次。

frame 加一道防呆（只在測試和開發模式下斷言，正式版不擋畫）：資訊區裡出現 `press` 就丟錯，控制區列數大於 `ctrlCap` 也丟錯。這樣以後新增頁面，第一次跑測試就會抓到，不靠人記得。

### 3.2 待決頁：控制區的內容

由下往上：

| 順序（由下往上） | 列 | 可點 | 說明 |
|---|---|---|---|
| 1 | 送出列：`[s] 送出已選 N 張 · 另 M 張未選`；預覽時換成預覽列（現行 r11 #3 行為不變） | `key:s`／`key:y` | 最靠近 prompt |
| 2 | 附註列：`m 附註：<已寫的附註或提示>` | `key:m` | 文字模式時這列變成輸入列 |
| 3 | 選項列：`a 合併 ✧`、`b 再審一輪`、`c 待辦`（一個選項一列，✧＝建議） | `key:a`…`key:c` | 字母照 `pickKeys`（R6） |
| 4 | 換卡器：目前這張卡的前後各 k 張，一列一張，目前這張標 `▸` | `key:card:<id>` | 取代 V3 上半部的可點清單；k 依尺寸決定（3.3 節） |

資訊區由上往下的固定順序（g1 54c21db4）：

1. 分類標題「待決 21 張 · 第 3 張」：釘住，永遠不被截。
2. 「等你動手」區塊：最多 3 列，放不下時收成一列「等你動手 N 張」。
3. 「↑ 上面還有 N 列」：背景被截掉時才出現。
4. 背景：唯一可以捲動的部分，用 PgUp／PgDn 捲；鍵位寫在下框線提示裡。
5. 建議。
6. `▸` 目前這張卡的標題和問題：緊貼控制區，最後才被截。

空間不夠時從背景開始截，然後是等你動手區塊（收成一列），分類標題和第 6 項不截。

### 3.3 退化階梯（控制區放不下時）

frame 給的 `ctrlCap` 決定用哪一階，取放得下的最高階：

| 階 | 換卡器 | 選項 | 附註＋送出 | 總列數 |
|---|---|---|---|---|
| L0 | 5 列（前後各 2） | 一個一列（≤3 列） | 各一列 | 10 |
| L1 | 3 列（前後各 1） | 一個一列 | 各一列 | 8 |
| L2 | 1 列：`‹ p 3/21 n ›` | 一個一列 | 合成一列：`m 附註 · [s] 送出 N 張` | 5 |
| L3 | 1 列 | 合成一列：`a 合併 ✧ · b 再審 · c 待辦`（每段各自可點） | 合成一列 | 3 |
| L4 | 不顯示（p／n 鍵照樣有效，寫在送出列） | 合成一列 | 合成一列：`p/n 3/21 · m 附註 · [s] 送出` | 2 |
| L5 | 不顯示 | 不顯示 | 一列：`▸ 3/21 · Enter 展開` | 1 |

**選階用實際需要的列數，不用上表的固定數字**（g1 4c573674 第 2 點）：每階的列數＝換卡器列數＋選項列數（L0–L2 是選項個數 n，L3–L4 是 1）＋附註／送出列數。從 L0 往下找，第一個 ≤ `ctrlCap` 的就是要用的階。上表的 10／8／5 只是 n＝3 時的值。

**選項超過寬度或超過 3 個**：L0–L2 每列一個，n 再大就照公式往下退階。L3、L4 合成一列時，放不下的選項收成 `… 另 N 項 · o 看全部`。按 `o` 時，選項清單暫時取代換卡器的位置（仍在控制區內，列數不超過 `ctrlCap`），Esc 收回。字母照 `pickKeys(全部選項)` 算，**不是**照畫出來的那幾個算，所以被收起的選項照樣可以直接按字母選（g1 296018f1）。

**各階的可點元素**（g1 d1ce5683）：

| 階 | 下半部一定要有的 `press` |
|---|---|
| L0–L2 | 每個選項 `key:<字母>`、`key:m`、`key:s`、換卡器（L0／L1 每列 `key:card:<id>`，L2 `key:p`／`key:n`） |
| L3 | 選項列每段 `key:<字母>`、`key:p`／`key:n`、`key:m`、`key:s` |
| L4 | 選項列每段 `key:<字母>`、合成列的 `key:p`、`key:n`、`key:m`、`key:s` |
| L5 | 一列：`a/b/c 選 · s 送 · 3/21`，全部是鍵盤鍵；唯一可點的是 `Enter 展開`，按了打開 docked pane 的待決頁、游標在同一張卡（g1 56cd9f57） |

**三種輸入狀態**（g1 d1ce5683）：
- **一般狀態**：照上表。
- **附註輸入**（按 m）：附註列變成輸入列，選項列保留；送出列改成 `Enter 確定 · Esc 取消`。這時下半部一定要有的 `press` 是輸入列和 `key:esc`。
- **送出預覽**（第一次按 s）：預覽列取代選項列和換卡器，最多 `ctrlCap − 1` 列，最後一列是 `[y] 確定送出 · Esc 回去`；放不下的卡收成「…另 N 張」。

附註太長時，在附註列內截斷並加 `…`，不換行。

各尺寸預期落在哪一階（H＝含框線的框高）：

| 模式與尺寸 | H | ctrlCap | 階 |
|---|---|---|---|
| docked 200x50 | 約 48 | 23 | L0 |
| docked 120x40 | 約 38 | 18 | L0 |
| docked 80x24 | 約 22 | 10 | L0 |
| boxed 200x50 | 17（宿主實測） | 8 | L1 |
| boxed 120x40 | 13 | 6 | L2 |
| boxed 80x24 | 5 | 2 | L4 |

實際的 H 由宿主決定；測試要同時跑「終端尺寸」和「宿主框高」兩組（補 G2）。

### 3.4 C 雙欄（boxed，bodyColumns ≥ 83）

沿用 PM 的欄寬規則（bodyColumns ≥ 83 雙欄、每欄 ≥ 40、±2 hysteresis）。改動有兩點：

1. **左欄清單變成不可點的資訊**（目前這張標 `▸`，沒有 `press`），點選換卡改由下半部的換卡器負責。左欄清單和右欄詳情都在資訊區，控制區照 3.2 節橫跨整個寬度。列入偏離 D2。
2. **列數門檻改用資訊區列數**（g1 f532cf4a）：控制區搬下來之後，boxed H＝17／13 時資訊區只剩約 7／5 列。原本「maxRows < 10 收清單」會讓宿主實際的 boxed 尺寸全部收成清單。改成：資訊區 ≥ 6 列才雙欄，否則單欄（只顯示目前這張卡）。maxRows < 10 仍然收成緊湊清單（L4／L5）。雙欄時左欄已經列出卡片，換卡器固定用 1 列（`‹ p 3/21 n ›`），不再上下各列一次清單。這一點改了 PM 01M8384QH4 的門檻，列入偏離 D5，要 PM 確認。

### 3.5 其他頁

現行實測其他頁沒有違規。本計畫只做兩件事：(1) 套用 3.1 的 frame 規則，把現有 `actions` 照新名稱接上；(2) 把 forge、quota、room 加進 R1 檢查（G1）。forge 頁的 ★ 捲軸是捲軸，不是按鈕，不帶 `press`；如果量出來有，就照 3.1 搬下來。

### 3.6 band 與 Pane 一起設計（R3、R4）

- **分工**：band 是底部操作熱區（一列、左右分區，11-23 計畫已上線），Pane 負責瀏覽和細節。band 本來就在最下面，不受 R1 影響；R3 只核對一次：展開鍵固定在右端、不和 Claude Code 的 `[-]` 衝突，在 200／120／80 三種寬度下截圖確認。
- **共用狀態**：band 的「待決 N」段和 Pane 待決頁共用同一個選取游標（`v74.nav.cursor`）。點 band 的待決段：打開 Pane 並跳到待決頁的同一張卡；Pane 裡換卡，band 的左段提醒也跟著換成那張卡的標題。這部分現在是不是已經共用，實作第一步先量；已經共用就只補測試。
- **forge-stats 不開第二個 pane（補 G3）**：`/forge-stats` 不再開 forge-stats 自己的 Pane，改成打開 live pane 並切到對應頁籤（寵物→0、用量→5 花費、艦隊→7）。forge-stats 的 band 段和 `pet.json` 契約不變。
  - **跨外掛契約**（g1 edb50e24）：forge-stats 不呼叫 autopilot 的程式碼。`/forge-stats [pet|usage|fleet]` 用宿主的 UI API 開啟 component `Pane`、plugin `autopilot`、requestId `live`，帶 `view: { page: 'pet' | 'spend' | 'fleet' }`。live pane 在 render 時讀 `view.page` 並切頁，這一步是 AP 的單元 U3b。宿主如果不允許外掛開啟別的外掛的 Pane（U0 先試），就退回：`/forge-stats` 只印一行「已併入 live pane：按 0／5／7」，不開任何 pane。
  - **內容對照先做**：U0 先逐項對照 forge-stats Pane 三頁和 live pane 0／5／7 頁。live pane 缺的欄位寫成 AP 單元 U3c，補齊並審併之後，U4 才退役 forge-stats Pane。不能少東西。
