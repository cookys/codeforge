# band 單列排版計畫與真 render mock（單 01M837HGTX，2026-11-23）

> 範圍：提示框上方那一列 band。操作員原話（11-23）：「把他排好看、UX 好一點，讓左右、快捷鍵都有固定位置可以展開收闔、內容點擊都會跳到對應地方，然後讓排版整齊一致一點，提供良好 UX」。

## 1. 設計規則

1. **固定位置、固定寬度**：左＝提醒或待決（可變寬，吃剩餘寬度）；中＝產線、來源、待決、QC；右＝tok/s、sparkline、寵物。每個中右段有固定欄寬（ 7、 16、 13、 6、 11、sparkline 6、寵物 12），數字變了只在自己那格內變，別的段不會跳位置。
2. **提醒太長截斷並用 ⋯ 收合**，永遠不換行。
3. **窄視窗依優先序收段落**：先收寵物，再 sparkline，再 QC、來源，產線與 tok/s 與待決最後才收；提醒最少保留 8 欄。段落之間永遠有分隔 ，不擠在一起。
4. **宿主上限**：band 只有一列；寬度用 （宿主已扣掉右邊 5 格的 ）；不自己算終端寬度。
5. **每段可點、有快捷鍵、跳到對應頁籤**（實作時沿用 pane 的頁籤：待決→2、產線→3、QC→4、ϟ→5 花費或 7 艦隊、來源→8 待辦）；整列可展開或收合（／，點一下縮成一行），**收合功能要加回歸測試**（之前消失過）。快捷鍵只在視窗內有效（宿主限制）。
6. 與待決頁 C 的退化規則一致（PM 裁定）：看 ，不看終端寬度；≥83 欄 C 雙欄、<83 單欄、±2 欄 hysteresis；<10 時單欄收成一行一張卡。80x24 時 band 至少保留一行，不能整個不見。
