# band 單列排版計畫與真 render mock（單 01M837HGTX，2026-11-23）

> 範圍：提示框上方那一列 band。操作員原話（11-23）：「把他排好看、UX 好一點，讓左右、快捷鍵都有固定位置可以展開收闔、內容點擊都會跳到對應地方，然後讓排版整齊一致一點，提供良好 UX」。
> 本文件是計畫加 mock；實作與兩家 UX 評審見末節。mock 是在真 Claude Code 全螢幕（sandbox tmux，不碰 tmux 0）用一個靜態 mod（假資料）畫出來的；每張圖三列：第一列是現行 band，第二列是本計畫的版面，第三列是寬度與留下的段落。

## 1. 設計規則

1. **固定位置、固定寬度**：左＝提醒或待決（可變寬，吃剩餘寬度）；中＝產線、來源、待決、QC；右＝tok/s、sparkline、寵物。每個中右段有固定欄寬（待決 7、產線 16、來源 13、QC 6、ϟ tok/s 11、sparkline 6、寵物 12），數字變了只在自己那格內變，別的段不會跳位置。
2. **提醒太長就截斷並用 ⋯ 收合**，永遠不換行。
3. **窄視窗依優先序收段落**：先收寵物，再 sparkline，再 QC（無告警時）、來源、tok/s、產線；待決最後才收；QC 告警時不收；提醒最少保留 28 欄。段落之間永遠有分隔「 │ 」，不擠在一起。
4. **宿主上限**：band 只有一列；寬度用 bodyColumns（宿主已扣掉右邊 5 格的 [-]）；不自己算終端寬度。
5. **每段可點、有快捷鍵、跳到對應頁籤**（沿用 pane 的頁籤：待決→2、產線→3、QC→4、ϟ→5 花費或 7 艦隊、來源→8 待辦）；整列可展開或收合（▾／▴，點一下縮成一行），**收合功能要加回歸測試**（之前消失過）。快捷鍵只在視窗內有效（宿主限制）。
6. 與待決頁 C 的退化規則一致（PM 裁定）：看 bodyColumns，不看終端寬度；≥83 欄 C 雙欄、<83 單欄、±2 欄 hysteresis；maxRows<10 時單欄收成一行一張卡。80x24 時 band 至少保留一行，不能整個不見。

## 2.1 評審意見與回應（codex 6/10；carbon 5.6/10；兩家都判有 Critical，第 3 版逐條回應，等第二輪評審）

| 意見 | 回應 |
|---|---|
| 窄版待處理標題看不到（兩家 Critical） | 提醒最少 28 欄；80 欄時完整標題仍在（見上圖）。 |
| QC 告警在窄版被收掉（carbon C1） | 告警態的 QC（▲）優先序提到最高，不收；平時無告警的 QC 才依序收。80 欄圖已示範：待決、QC 留下，產線以外的次要段先收。 |
| 固定格寬無溢位契約（兩家） | 每個數字上限 99+，右對齊（第 3 版圖已右對齊）；tok/s 超過 999 顯示 1k+；完整值在對應頁。實作加測試：多個計數同時變長、CJK 顯示寬度、分隔位置不變。 |
| 缺資料／資料過舊看起來像正常（carbon C3） | 每段有三態：正常、過舊、缺資料。過舊（資料超過 5 分鐘未更新）＝該段文字變暗並在數字後加「?」，且該段的標籤前綴改成「⌛」；缺資料＝數字位置顯示「—」。過舊與缺資料不改變段落寬度。實作要有每段三態的測試與 S5 截圖。 |
| 順序與正文矛盾、鍵位跳號（carbon M1） | 順序回到現行與正文一致：產線、來源、待決、QC、tok/s。每段以它開啟的頁碼開頭（3、8、2、4、5），畫面上就是鍵位提示；跳號是因為順序沿用現行，操作員要求的是「固定位置」而不是重排。ϟ 唯一目的地 5 花費。 |
| 數字靠左造成抖動、缺語意色與雙主題（carbon M2） | 數字右對齊已修。語意色（實作時依 PALETTE，一列最多一個黃色焦點）：error＝✗ 與 QC 告警，warning＝待決有建議，inactive＝過舊與缺資料，其他中性；實作要附淺色與深色主題各一張截圖（S1），本版純文字 mock 未驗配色，尚未驗證。 |
| 展開收合符號與單列矛盾、無鍵盤（carbon M3、codex Minor） | ▾展開＝目前收合（點展開）、▴收合＝目前展開（點收合）。宿主限制每個 plugin 的 band 只有一列，所以「展開」不能多畫一列；實作前先用真 Claude Code 驗證，驗證前計畫以「展開＝切到 pane 1 現況頁」為準。鍵盤：實作時與 keys.ts 對表選一個未被佔用的鍵，在提示列顯示。狀態按視窗保存。 |
| 新舊列假資料不同（carbon m1） | 第 3 版已用同一組資料；現行第 4 項產線計數 ⋯（等待數）保留在新版。 |

## 3. 實作與驗收計畫

- 範圍：autopilot mods/live/band.tsx（band 單列）。與 C 的 maxRows 修正單 01M837ZECP 相鄰，兩單同一批改、同一次交給 autopilot 審併，避免同檔改兩次。
- 實作交便宜席，本席審；測試：每段固定寬度（斷言數字變化不改其他段的欄位置）、優先序收段、點擊與快捷鍵路由、展開收合回歸測試、四種尺寸真終端實拍。
- 驗收：操作員的 PM pane 實拍（hangar 新 tmux 窗），附四尺寸並排與差異清單；兩家 hetero UX 評審都 ≥8/10。

## 4. 風險

- 80 欄時提醒只剩一個字元寬，丟失「要你決定」的語意：實作時 80 欄應先收來源、QC 並讓提醒至少留 14 欄（mock 的收段規則已用 REMIND_MIN=14，但 80 欄仍只剩 ⋯，因為待決、產線、tok/s 三段加分隔已占滿；要再收 tok/s 或縮短產線段）。
- 現行 band 的 ⓘ 說明圖示在本計畫沒有位置，需決定是否併入 ▾ 展開後的列。
