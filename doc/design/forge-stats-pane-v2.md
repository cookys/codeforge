# forge-stats Pane v2 視覺設計規格書

本文件定義 `plugins/forge-stats` 第二版（v2）之資訊架構、版面配置、動態高度預算、鍵位對應與語意配色，沿用 11-10 定案之 Fable r4b 版面語言，解決舊版「高度過低、上方塞滿 25 列空白、切成三個單欄頁籤、預設頁看不到關鍵異常與配額」的問題。

---

## 1. 資訊架構（Information Architecture）

### 1.1 版面骨架與設計語言（沿用 Fable r4b）

1. **左側固定標籤欄（Left Label Gutter，固定 9 格寬）**：
   - 第 `1..7` 格（7 格）：2 個正體中文字標籤（4 格）＋ 3 個半形空白（3 格）；同區延續列（continuation row）填 7 個半形空白。
   - 第 `8` 格（1 格）：垂直分隔線 `{subtle}│{/}`。
   - 第 `9` 格（1 格）：1 個半形空白。
   - 第 `10..W` 格（`W - 9` 格）：主體內容區（160 寬時為 151 格、120 寬時為 111 格、80 寬時為 71 格）。
   - **無外框、無水平分隔線、無區塊標題列**：完全靠左側標籤文字與標籤語意色（`inactive` → `warning` → `error` → `inactive` → `merged`）區分層級，節省每一列高度。
2. **三個垂直閱讀與操作層次（由上而下）**：
   - **頂部狀態帶（`狀態`，固定第 1 列，純閱讀不可按）**：單列濃縮全艦隊與本機即時指標，帶上每一組指標皆一對一對應底部操作區的一個按鍵或頁籤。
   - **主體資訊區（第 2 列至倒數第 3 列，預設頁為「總覽」）**：依操作員處理急迫度由上而下排列為 **(a) 待決**、**(b) 卡住**、**(c) 各池**、**(d) 交辦** 四個區域。
   - **底部操作區（固定最後 2 列：`分頁`＋`按鍵`）**：包含頁籤切換列與即時有效按鍵提示列，計入整體高度預算。
3. **舊版頁籤收斂與 Usage 頁去留提案**：
   - **頁籤由 3 個減為 2 個**：預設頁為 **「總覽」**，次要頁籤為 **「寵物」**（可按 `Tab` 或 `p` 切換）。
   - **Usage 頁（逐 model 成本）處置提案：取消獨立 Usage 頁籤，總額收斂至頂部狀態帶、明細併入「寵物」次頁下半部**。
     - **理由一（決策依據轉移）**：操作員日常調度看的是「各池 7d/5h 額度剩多少、何時重置、哪一池快耗盡或閒置」（已在預設頁「各池」區完整呈現），而非單一 model 的歷史 token 計費。
     - **理由二（消除重複與切換成本）**：舊版 Usage 頁每個 model 一列重複顯示同質欄位，獨立成頁既浪費頁籤又迫使操作員來回切換。將當日總花費（`$42 ▰▱▱▱▱`）與即時吞吐（`ϟ 55 tok/s ▆▄▅█▅`）常駐於第 1 列狀態帶，並將本機工作階段（Session）各 model 成本拆解併入「寵物」次頁底部的 `本機` 區（僅佔 3 列），即可在維持 2 個頁籤的前提下保留完整資訊。

### 1.2 預設頁「總覽」各區定義、排序規則與去重規則

| 順序 | 左欄標籤 | 標籤語意色 | 收錄資料來源與條件 | 區內排序規則（由上而下） |
|---|---|---|---|---|
| **頂列** | `狀態` | `inactive` | `brief.counts`、`fleet-quota` 摘要、本機 `$ / tok/s`、Ferris 等級、資料新鮮度 | 固定順序：`▲待決` → `艦隊 ⊘ ⋯` → `池警訊` → `$ bar` → `ϟ tok/s sparkline` → `Ferris` → `ⓘ 新鮮度`（窄視窗依宣告順序丟棄次要項） |
| **(a)** | `待決` | `warning`（0 筆時 `inactive`） | `fleet.brief/1` 中 `kind == "needs_human"` 之項目 | 固定只佔 **1 列**。顯示待決總數 `N`，並取 `since_ms` **最舊（等最久）** 一張卡的 `subject.display`、截斷標題、`text` 與等待時間；右側顯示 `[d] 跳 autopilot`。決策卡全文只在 autopilot pane 繪製。 |
| **(b)** | `卡住` | `error` | `fleet.brief/1` 中 `kind` 屬於 `{offline, stuck, waiting_pm, high_context}` 且未在其他高優先區出現之項目 | 1. 先依 `level`：`red` 在 `amber` 前面。<br>2. 同 `level` 依 `kind` 嚴重度：`offline`（整機離線）> `stuck`（逾時無回報）> `waiting_pm`（等 PM）> `high_context`（高上下文）。<br>3. 同 `kind` 依 `since_ms` **越舊越前面**（卡最久的排最頂端）。<br>4. 若全區為 0 筆，整區收起佔 **0 列**。 |
| **(c)** | `各池` | `inactive` | `codeforge.fleet-quota/1` 之所有帳號列（含 `weekly`、`fiveHour`、`warn`、`state`、`sourceNote`） | 1. **有實測資料且 `warn == "short"`**（額度吃緊／將耗盡）：依 `weekly.pct` **由高到低**排序（`smith1 99%` → `smith2 82%` → `codexseat 54%` → `grokbot 39%` → `kimi 18%`）。<br>2. **有實測資料且 `warn == "waste"`**（重置前用不到目標 `useTarget=85%`）：依距離 `resetsAt` 由近到遠排序（`team-a 9.6%`）。<br>3. **有實測資料且 `warn == null`**：依 `weekly.pct` 由高到低排序。<br>4. **無自動來源（`state == "no_source"`）**：先排需操作員介入的 `needs_token`（2 列），最後排僅網頁無 API 的 `web_only`（4 列）。在 120/80 窄高度下自動將 `no_source` 合併為 1 列摘要。 |

| **底 2** | `按鍵` | `merged` | 當前畫面有效按鍵提示 | 固定最後第 1 列。只顯示當前狀態下可按的活鍵（live keys）。 |

### 1.3 跨區去重規則（Deduplication Rules）

為落實 PM 規範「**同一件事只出現一次。例如一條線既卡住、又有一張卡在等操作員，只能出現在一個地方**」，前端渲染前執行以下三階段去重：

1. **第一階段：`kind` 分流與背景雜訊過濾**：
   - `needs_human` 僅歸入 **(a) 待決區**。
   - `offline`、`stuck`、`waiting_pm`、`high_context` 候選歸入 **(b) 卡住區**。
   - `origin == "operator"` 歸入 **(d) 交辦區**。
   - `waiting`（範例中 9 筆殘留／等待對象寫錯）與 `info`（範例中 1 筆等待已結束）屬低優先背景紀錄，**不進入主體任何一列**，僅將筆數合計（`9 + 1 = 10`）顯示於第 1 列狀態帶的 `{inactive}⋯10{/}`。
2. **第二階段：跨區主鍵與執行線（Lane）去重**：
   - **優先序**：**(a) 待決 (`needs_human`) > (d) 交辦 (`origin=operator`) > (b) 卡住 (`offline/stuck/waiting_pm/high_context`)**。
   - **去重邏輯**：
     - 以 `ids.task_id`（同一任務）及 `subject.display`（同一條執行線）作為去重鍵。
     - 若某條線（`subject.display`）已有未決之 `needs_human` 決策卡在等操作員回覆，代表該線停滯之根本原因為「等待操作員拍板」，故只計入 **(a) 待決**，並從 **(b) 卡住** 剔除，避免操作員在「待決」與「卡住」看到同一條線被重複告警。
     - 若某項任務已列於 **(d) 交辦**（如 `PM` 的「twgame 新帳號註冊」等操作員），且在 `brief.json` 產生同任務 `ids.task_id` 的狀態項，則保留於 **(d) 交辦**，不在卡住區重複列出。
   - **範例資料實際去重結果**：
     - 題目範例中 `counts.red` 原為 8 筆（`offline` 2 筆＋`stuck` 6 筆）。
     - 其中 `pm（host-a）` 在 `needs_human` 有 2 張待決卡（「下次到現場時，照附件量 24 項…」、「網頁總覽要不要另外發一把…」），同時又在 `stuck` 有一筆「整理這週的待辦並派工」。依「一條線既卡住、又有一張卡在等操作員，只能出現在一個地方」，`pm（host-a）` 歸入 **(a) 待決**（計入 `▲3`），並自 **(b) 卡住** 剔除。
     - 因此 **(b) 卡住** 去重後實際有效筆數為 **7 筆**（依排序為：`host-g`、`host-f` 2 筆離線，以及 `delta`、`kilo`、`cobalt`、`ember`、`falcon` 5 筆卡住），頂部狀態帶同步顯示為 `{error}⊘7{/}`。
     - 至於 `cobalt（host-b）` 與 `ember（host-d）` 雖皆執行「跑完 nightly 基準並把結果寫進報告」，但因 `subject.display` 分屬不同主機的兩條獨立線，故保留為獨立 2 列。

## 2. ASCII Mockups（含逐字元寬度標註）

### 2.0 字寬計算規範與欄位標尺說明

- **字寬基準（Display Cell Width，與 Fable r4b 完全一致）**：
  - **2 格寬（Fullwidth = 2 cells）**：所有正體中文漢字（CJK Unified Ideographs）及全形標點符號 `（` `）` `：` `，` `、` `。` `；` `「` `」` `？`。
  - **1 格寬（Halfwidth = 1 cell）**：所有 ASCII 英數字元、半形空白、框線 `│`（U+2502）、方塊與半格字元 `▰` `▱` `▆` `▄` `▅` `█` `▀`、以及單格狀態與結構符號 `▲` `⊘` `⋯` `ϟ` `ⓘ` `▸` `○` `◐` `✓` `★` `·` `—` `…` `↓` `→` `!`。
  - **語意色標籤不佔寬度**：`{warning}`、`{error}`、`{merged}`、`{inactive}`、`{subtle}`、`{claude}`、`{suggestion}`、`{/}` 為 Fable r4b 語意色標記，實際渲染寬度為 **0 格**。
- **呈現方式**：以下每個情境皆提供 **(1) 帶頂部逐格標尺之 Fable r4b 語意色標記版 Mockup**、**(2) 去除色碼標籤之純文字格線對齊預覽**（讓每個字元直接對齊上方 `1234567890` 標尺）、以及 **(3) 逐列逐欄實際格數驗算表**。

### 2.1 Mockup 1：160x40 終端，完整資料量（觸及 60% 上限 = 24 列）

|---|---|---|---|---|
| 1 | **預設首頁內容** | 預設停在單欄頁籤（Pet 或單一視圖），看不到艦隊卡住與各池重置倒數。 | 預設頁改為 **「總覽」**，一頁整合「待決、卡住、各池、交辦」四大核心資訊。 | 把操作員每個 Session 最常巡檢的異常與配額直接放在首頁，省去切換頁籤。 |

## 7. 要求 fleet 補的欄位（給 `~/.local/state/fleet/brief.json` 的擴充建議）

本設計在主體與 Mockup 中**完全只使用現有 `fleet.brief/1` 與 `codeforge.fleet-quota/1` 既有欄位**。為讓 **(d) 操作員交辦的事（`origin=operator`）** 與跨區去重在正式接線後無需前端猜測，建議 fleet 端後續在 `brief.json` 補充以下欄位：

1. **新增或正式定案操作員交辦項目之識別欄位**：
   - 方案 A（於 `items[]` 內加欄位）：在 `brief.items[]` 既有結構新增 `"origin": "operator" | "fleet" | "schedule"`，並允許交辦事項在正常執行中時以 `"kind": "operator_task"`（或 `"level": "info"` 搭配 `"origin": "operator"`）寫入 `brief.json`，使「進行中（如 `forge-stats 介面重做`）」與「等回報（如 `gpu-host-1 換 live 版`）」的交辦項目也能出現在 `brief.json` 中，而非只有卡住時才出現。
   - 方案 B（頂層獨立陣列）：在 `brief.json` 頂層新增 `"operator_tasks": [{ "id", "assignee", "title", "state": "needs_human" | "waiting_reply" | "in_progress", "since_ms" }]`。
2. **補齊 `generated_at_ms` 頂層時間戳**：
   - 在 `brief.json` 頂層提供 `"generated_at_ms": <epoch_ms>`，供 mod 直接比對 `Date.now() - generated_at_ms > 300_000` 判定是否超過 5 分鐘未更新（不必單靠檔案系統 `mtime`）。
3. **統一下游 `ids` 關聯鍵（用於精確跨區去重）**：
   - 確保 `items[].ids` 內固定包含 `"lane_id"`（對應執行線，如 `"pm@host-a"`）與 `"task_id"`（對應派工任務 ID），讓前端執行「同一條線／同一任務既卡住又有待決卡時只出現一次」去重時，不必僅靠 `subject.display` 字串比對。
