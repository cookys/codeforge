# band 單列排版 UX 評審

評審範圍：僅依 [排版計畫](../../../plans/2026-11-23-band-layout.md) 第 1–4 節的四尺寸文字 mock，依 [UX 閘門](../../../specs/forge-stats-ux-gate.md) 評估操作員每日在終端機掃讀、找問題、跳轉處理的體驗。以下定位皆指各 mock 第二列；不是實作、點擊或真終端測試結果。

## 分數

| 項目 | 分數 | 理由 |
|---|---:|---|
| 好用 | 3/6 | 單列與分隔有助掃讀，但窄版藏掉待決標題、快捷鍵不可見、跳轉目的地不唯一。 |

## 問題

1. **Critical — 待處理標題在窄版不可見**（好用 1；閘門 Critical「需要處理的項目看不到」）。80x24 左側提醒欄：有一張需要決定是否合併的卡 → 錯誤畫面只顯示「▲ 要你決定：⋯」，沒有卡片標題；120x40 同欄只剩「合併 sha⋯」。操作員無法第一眼辨別要決定哪件事，兩張同前綴卡也無法區分。待決數字還在並不能替代標題。應先收來源、圖形、寵物與速率，保留有辨識力的標題；必要時提供精簡且唯一的任務識別。
2. **Major — 入口與鍵位無法從畫面學會**（好用 5）。四尺寸的待決、產線、來源、QC、速率欄與右端 ▾ 都沒有鍵位提示；操作員第一次看到「待決 4」需猜怎麼進入。計畫第 1 節第 5 點還把 ϟ 指向「5 花費或 7 艦隊」，同一可見入口可能去兩處；來源標籤與「8 待辦」也不直觀。需定義唯一目的地，於靠近輸入框的固定提示列列出對應鍵，並說明隱藏段落是否仍可用鍵進入。
3. **Major — 固定格寬欠缺溢位契約**（好用 4、fancy 11；條件風險，未宣稱已發生爆格）。四尺寸產線欄都是「✗14」，待決都是「4」，沒有三位數案例。若產線從 ✗14 變 ✗140，其他計數也一起增長，未裁切的內容可能推動右側分隔；直接裁切又可能隱藏失敗數。需依終端顯示欄寬右對齊數字，定義上限縮寫及可查看完整值的入口，驗證多個計數同時變長且分隔位置不變。
4. **Major — 次要裝飾擠壓主要工作**（好用 1、fancy 9）。120x40 的提醒已截到「合併 sha⋯」，右側仍有 sparkline、寵物與速率；80x24 仍保留來源。每天掃讀時，操作員先看到裝飾或來源，卻必須跳頁才能知道要處理的事。應以提醒的可辨識內容作為收段條件，而非只保證剩幾個欄位。
5. **Minor — 展開收合符號語意及狀態未定義**（好用 5）。四尺寸右端都是 ▾，與現行列 ▴ 相反；計畫又稱「縮成一行」，但 mock 已是一行。操作員點擊後無法預期會顯示哪些內容。需補展開與收合兩態、可點範圍、對應鍵及狀態保存規則。

## 指定問題逐題回答

- **數字變長會不會爆格？** 目前無法保證不會。✗14→✗140 增加一欄；若其他數字不變，產線 16 欄的尾端空白可能吸收，不能只因增一位就斷言爆格。待決 21→210 的「待決 210」已占 7 顯示欄，剛好用完規定寬度；若 padding 算在格內便需另處理。四張 mock 的「待決 4」沒有覆蓋此邊界。應補三位數、多計數同增、超上限與 CJK 顯示寬度案例；禁止靜默截掉關鍵數字或推擠下一格。
- **80 欄提醒只剩 ⋯ 可接受嗎？** 不可接受。實際第二列還有「要你決定」前綴，但任務語意只剩省略號；數字只能說有事，無法說是哪件事。這違反第一眼看到最舊待決標題的要求。優先回收次要段落；完整標題可展開查看，但收合態仍需有辨識線索。
- **點擊與快捷鍵映射清楚嗎？** 不清楚。200x50、160x45 的完整段落也沒有可按提示；120x40、80x24 再隱藏部分段落後更難探索。計畫有列頁碼，mock 沒呈現提示列，且 ϟ 有兩個目的地。需建立「段落標籤—唯一頁面—按鍵」對照，標明提醒文字、分隔線與箭頭各自的點擊範圍，測試滑鼠與鍵盤到同一目的地。mock 未提供實際互動證據。
- **收合需要記住狀態嗎？** 需要，至少同一視窗／工作階段內跨刷新及切頁應保留使用者選擇，避免每天重複收合或刷新後擠走對話。跨重新啟動是否保存可另定，建議按視窗保存；終端縮窄導致自動隱藏段落，不應覆寫手動展開偏好，放寬後應恢復。應補「手動收合→刷新／切頁→仍收合」與「縮窄→放寬→恢復偏好」案例。
