2. **Major — 缺待決來源時仍宣告「無待決」**（好用8）。位置：T state3的 `200c missing brief/quota`、`80c missing brief/quota` 兩列，`band-onerow.ts:328–334`。輸入reminder.state=missing、pend.count=null/state=missing → 左側顯示無待決，右側待決—。操作員先掃左側會把未知誤讀成已確認沒有事；應顯示待決資料缺失，只有正常且count=0才用無待決。右側—與inactive確實有別於完整正常態，因此不把整列判成「缺資料看起來全正常」Critical，但左側肯定語句仍須修正。測試通過正好證明現有測試未檢查這個語意。
3. **Major — 操作與資料追溯的驗收仍未閉合**（好用5、8；證據缺口，並非斷言handler故障）。位置：S-120x40-p2.txt:33、S-80x24-p2.txt:17–18、K-200x50-Esc.txt:43/47、T states4/5。使用者需收合pane或確認過期資訊 → 已能看到w，但未提供取得鍵盤焦點的實際路徑、真w收合／展開往返、刷新／切頁／縮窄放寬保留偏好、提醒／分隔／箭頭滑鼠熱區與隱藏數字鍵路由。Esc後仍有「鍵盤在pane」，需後續輸入探針證實焦點。6m/12m雖有~/?，沒有對應頁的來源、年紀、讀取失敗原因與完整值（含5花費吞吐量）。補操作收據及目的頁即可，不必為此製造live異常。state5只切expanded參數，不能代替宿主行為；短背景卡e/PgDn/Down畫面不動亦不能當作捲動故障。80欄Enter後可答卡也尚未交。
