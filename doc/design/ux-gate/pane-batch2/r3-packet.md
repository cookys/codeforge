# autopilot-live pane 共用 TUI 第 2 批 — UX 閘門第 3 輪（最後一輪）（獨立評審）

你是終端機 UX 總監。請依下方評分表（原文）以及兩個**必過項**，獨立評這次的 pane 改版。全程用正體中文。

## 這次改了什麼
autopilot-live pane 原本的 7 頁，加上 console 的 5 頁，合成一套共用 TUI。8 頁依序是：1 現況、2 待決、3 艦隊、4 額度、5 派工、6 審查、7 花費、8 殘留；另外 9 是寵物，0 是 forge。第 1 批（1–4 頁）已經上線；這一批交第 1 批評審發現的修正，範圍還是 1–4 頁和 band。
受測版本是 autopilot @ 91bd6682d，base 是第 1 批上線版 083cf2e91。截圖是在真終端機（tmux）裡跑 Claude Code 2.1.327 載入這個 mod 拍的，用的是 console 模式。資料全是假的：fleet 指令換成假腳本，主機名是 h1–h6，線名是甲乙丙丁。

## 操作員和 PM 定的規則（違反就算缺陷）
- 分頁列固定在 pane 的**最後一列**，全畫面只能有**一條**分頁列，不能有獨立的「開面板」那一列。
- pane 高度固定，換頁或資料變動時版面不能跳。
- 資料只讀 bus。資料過期要標紅（✗），而且要寫出原因，原因**不截斷**。
- 額度的顏色：紅 = 會停擺而且沒有別的池可切；黃 = 預計會浪費 Y%（超過 5%）；綠 = 預計用到 95%–100%，或池已用完但席位已經切走。操作員原話：「不是 90-95，是盡量要用完!!!」
- 鍵表一張，每個鍵只有一種意思。host 只接受「一個數字或一個小寫字母」當 hotkey。數字切頁；z 折疊；o 對焦點列動作；f 填入提示列；待決頁 a–e 選、s 送出、h/l 換張、n 補充、u 撤回；i 說明。Enter 只按焦點所在的按鈕。焦點在提示列時，鍵一律交還給 Claude Code。

## 必過項（任一項不過，總分最多 5，而且列為 Critical）
1. **畫面不跳動**：30 格連拍（每格間隔 1 秒），過程包括換頁、展開／收合、對焦點列動作、換張、資料過期、關 pane 再開。結果在下方。
2. **沒有過渡產物**：不能有殘字、重複的分頁列、多出來的空白列，也不能有 host 畫出來卻不該出現的元件。內容中間或內容和頁尾之間的空白列算缺陷；全在內容上方的空白列依 PM 裁示豁免。

## 已知的 host 限制（不算缺陷，但可以評替代做法）
- pane 的寬度和位置由 host 決定：160 欄時，pane 在右側，約 70 欄寬。
- 帶 hotkey 的 Button，host 會在前面畫「鍵:」。分頁列「1: 現況 2: 待決…」的「N:」是 host 畫的。
- mod 收不到任意按鍵，只能收 hotkey 和焦點按鈕上的 Enter。
- 實測（2.1.327＋tmux）：pane 和 band 都拿不到鍵盤焦點（Ctrl+x Tab、Tab、點擊都試過），字母熱鍵進提示列；只有空提示列下的數字會按到分頁。所以本版每個熱鍵動作都另有一個看得見、點得到的 Button（G11），連拍時換頁用數字、其他動作用點擊。
- 80x24 時 pane 在提示列上方，host 只給它約 8 列；上方空白是 host 的對話區，pane 拿不到。
- 160 欄時 pane 在右側；pane 關著時，分頁改由 band 第 2 列畫（頁名，不綁數字，點了開 pane 到那一頁），所以關著的那幾格分頁列在 band 上，不在 pane 的位置。

## 評分項目

兩組項目合起來打一個總分（1–10），「好用」組權重較高：好用組有任何 Major 以上的發現，總分不得高於 7。每項寫它防的失敗。

### (a) 好用

1. **重要的事第一眼看到**：待決數與最舊一張標題、卡住的線、快用完的池，在 S1–S3 都不用捲動或切頁就看得到，且排在最上面。防：卡住的線排在第二頁，操作員沒看到。
2. **同一件事只出現一次**：一條線、一張卡、一個池在預設頁只出現在一處。防：同一張卡同時列在「待決」和「卡住」，操作員以為是兩件事。
3. **高度依內容**：總高度 ≤ `min(maxRows, floor(rows*0.6))`（TUX v1.4），沒有整列空白補位。防：內容 5 列卻佔 25 列，把對話擠走（11-17 操作員原樣抱怨）。
4. **80／120／160 欄都不截壞、不錯位**：CJK 依顯示寬度（2 格）算，超長標題以「…」截斷，欄位不錯位、不折行。防：80 欄時中文標題把用量欄推出畫面。
5. **按鍵在最底下、靠近輸入框**：鍵位提示固定在 pane 底部（緊貼輸入框），頂部狀態帶每一項都對到一個鍵；「待決」一鍵跳到 autopilot pane。防：看到「待決 3」卻不知道按什麼去處理。
6. **全中文**：畫面上的標籤、狀態、提示全部正體中文（帳號名、model 名、指令名等專有名詞除外）。防：英中混雜的標籤讓操作員停下來翻譯。
7. **格子少**：預設頁就是一頁；頁籤 ≤ 2（總覽 + Pet）；不加框。防：資訊切成三頁，每頁只有幾列（操作員原話「切分太多格」）。
8. **資料誠實**：數字取自 `fleet.brief/1`、`codeforge.fleet-quota/1` 原檔，不另算；過舊標年紀；缺資料說缺什麼。防：brief 已停更 1 小時，畫面仍顯示「0 卡住」。

### (b) fancy

9. **層次**：一眼分得出區塊（待決／卡住／池／交辦）與區內主次（主體 vs 次要說明），靠縮排、粗細與顏色，不靠框。防：所有列同一個重量，眼睛找不到起點。
10. **配色**：只有要操作員處理的用 warning，卡住／離線用 error，可按的用 merged，閱讀文字用 inactive；**淺色與深色終端機都要測**（S1 各交一張淺、深）。防：深色主題下 inactive 灰在淺色主題幾乎看不見；滿畫面紅黃，真正要處理的那項不突出。
11. **對齊**：同一區的欄位起點一致，數字靠右，bar 長度一致。防：用量 bar 長短不一，讀成用量差異。
12. **留白**：區與區之間至多一列空行，且只在有內容的區之間；不留裝飾性空白。防：留白吃掉 60% 上限內的內容列。
13. **整體質感**：與 autopilot pane 同一套視覺語言（Fable r4b：左標籤欄 + 一條垂直線、單列狀態帶），放在一起不像兩個產品。防：兩個 pane 並排時風格衝突。

## 嚴重度

- **Critical**（有一項就不過）：
  - 違反第 3 項的高度上限，或有整列空白補位；
  - 畫面上的標籤、狀態或提示出現簡體字；
  - 操作員需要處理的項目在 S1–S3 任一張截圖裡看不到；
  - 同一項目在預設頁出現兩次；
  - 顯示的數字與來源檔案不一致；
  - 缺資料或資料過舊時，畫面看起來像正常狀態；
  - 預設頁不是總覽。
- **Major**：會讓操作員多花一步，或讀錯一次。例如欄位錯位、截斷後兩列無法區分、配色語意錯了。
- **Minor**：措辭、間距、順序上的偏好。

發現一律要附一個做得到的情境：在哪一張截圖、哪一列，會讓操作員看錯或做錯什麼。沒有情境的意見只算備註，不影響分數。



## PM 裁示（第 1 批第 3 輪起適用，請照這條判讀，不要重開）
- **固定高度造成的空白列不算過渡產物**（PM 01M7NTXR，11-18）：pane 高度固定、畫面不跳，是操作員自己定的硬要求；內容少的時候，固定容器裡留空白列是這條要求必然的結果。
  - 條件：空白列一律放在內容**上方**，內容貼底、緊鄰頁尾的操作列和分頁列，中間**不准留洞**。
  - 判讀：中間有洞，或空白列在內容和頁尾之間，就算過渡產物（fail）；空白列全在上方，就不算。
- **高度上限只用在上下堆疊**：80x24 時 pane 疊在提示列上方，會佔掉對話區，所以有上限。160x40 和 120x30 時 pane 在右側跟對話區並排，不佔對話區的列；這時 pane 高度等於 host 給右側的列數，同一個終端尺寸下固定不變，分頁列緊貼在提示列上方。
- **窄寬度分頁列**：pane 寬度放不下一列時，分頁列固定 2 列（第 1 輪已認可）。放得下就是 1 列。

## 實作方的說明（autopilot 提供，不是評審結論；請對照截圖自行判斷）

Host 的 `Ofe` 以 `wo=Math.max(0,je-Hj(po,co))` 算正文預算，再傳入 `scroll:{offset:0,bodyRows:wo}`；`placement:Ze?"dock":"inline"`。正文容器有 `maxHeight:wo,overflowY:"hidden"`；inline 外層另畫 `borderStyle:co?"round":void 0`，其中 `co=!Ze`。因此 host 的 inline 底邊框在 mod 的正文視窗之外；mod 無法把自己的分頁列畫到那條邊框上。

Mod 路徑：``register.ts`` 的 Pane render 使用 `frameHeight(e.props.scroll?.bodyRows ?? 24, e.props.placement)` 傳給 `Pane`；``pages/frame.ts`` 的 `frameRows` 回傳正文預算列數，分頁列在最後；``pane.tsx`` 的 `framedView` 用相同高度，焦點 anchor 與最後一列共列。

本次確實找到 mod 可控制的多餘空白：舊 `frameHeight` 將 inline 再截成 24 列。W1 紅測試在 host 配給 25 列時收到 24；修正為完整使用 host 正文預算後變綠。測試涵蓋 160×40 dock 的 34 列與 120×30 inline 的 25 列，直接檢查正式 Pane 的列數與最後一列分頁按鈕；這些是注入的 host 配給案例，沒有宣稱已量到評審截圖的 host props。舊有 mounted dock／inline 測試也改驗完整配給。

## keyprobe（B56 真機按鍵驗收）

160x40 開 pane，縮到 80x24，依序按下列鍵；每鍵之後記錄三件事：分頁列選中哪一頁（tab，從分頁列顏色判斷）、pane 第一列（page，頁面捲動時會是「上面還有 N 行」，只供參考）、提示列內容（composer）。每一列最後的 ok 表示提示列是空的，而且分頁列選中的就是按下的那一鍵；BAD 表示其中一項不符。

```
1 key=2 tab=[2:待] page=[│ 待決] composer=[] ok
2 key=3 tab=[3:艦] page=[│ 艦隊] composer=[] ok
3 key=9 tab=[9:寵] page=[│ 寵物] composer=[] ok
4 key=1 tab=[1:現] page=[│ 現況] composer=[] ok
5 key=0 tab=[0:鍛] page=[│ 鍛] composer=[] ok
6 key=4 tab=[4:額] page=[│ 額度] composer=[] ok
```
