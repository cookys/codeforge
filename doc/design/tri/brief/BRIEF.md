# 題目：Claude Code 待決 pane 的完整 flow（獨立設計）

你是三位獨立設計者之一。三位拿到的題目相同，彼此看不到對方的稿子。請把**整個 pane 的完整操作流程**做成你認為最好的版本。操作員看了前幾輪的局部修正，說「這樣看我根本不知道怎樣改」，所以這一輪要交的是一套從頭到尾完整的設計，而不是單張修補。

## 背景

- 這個 pane 跑在 Claude Code 終端機裡。下方是 prompt 輸入框和 statusline。
- 「band」是貼在 prompt 上方的一條區域，可以展開。右側另有一個可停靠的「Pane」，只放文字。
- pane 要顯示這些東西：
  - **待決卡**：操作員要在 a/b/c 之間選一個並送出。
  - **「等你動手」卡**：操作員要照步驟親手做一件事，做完再回覆。
  - 艦隊（各 agent 的 tok/s）、花費、派工等其他頁。
- 可參考的資料，都在這個資料夾裡：
  - `v74/`：v7.4 的設計稿，S1–S10 加 SPLIT.md，是先前操作員認可的框架。
  - `r2/`：第二輪的實際畫面（.txt 和並排 png）。
  - `r3/`：第三輪修正版稿，含 README.md 和並排 png。操作員看不懂該怎麼改，就是指這一版。
  - `pane-design-language.md`：「操作員固定準則」R1–R7。
- 操作員過去的裁定，請當參考，可以推翻，但每推翻一條都要寫一句理由：
  - 操作區放在下方、靠近 prompt，資訊往上長。
  - band 和右側 Pane 是同一套設計。
  - forge-stats（艦隊 tok/s）併進 Pane，不另開第二個 pane。
  - 120x40 也要看得到全部選項，不用捲動。
  - 選項鍵照字母對應：a 就是第一個選項。
  - 少字：第一眼只看到問題、選項和建議。

## 要交的東西

1. **完整 flow，每一步一張畫面**，至少要有下面六步，順序和步數由你決定：
   - ① 平常沒事
   - ② 有待決卡要選
   - ③ 有「等你動手」卡：看步驟，做完後回覆
   - ④ 看一張卡的細節
   - ⑤ 切到艦隊頁或其他頁
   - ⑥ 送出後的回饋

   每張畫面都要標出「按了什麼鍵會到下一步」。
2. **三種寬度**：209x49、120x40、80x24。每一步在每種寬度各畫一張；**深淺兩種主題**由渲染管線一起產生。
3. **說明頁 `NOTES.md`**，內容包括：
   - 設計理念
   - flow 表：步驟、畫面、按鍵、到哪一步
   - 和第三輪最大的三個不同
   - 推翻了哪些裁定，各附理由
   - 自評缺點

## 輸出格式（必須照做，渲染管線和檢查腳本只認這個格式）

在你的資料夾 `doc/design/tri/<你的代號>/` 底下：

- `gen.py`：產生器。可以參考或複製 `brief/tools/gen3.py` 的片段模型和框線函式，但設計要是你自己的。
- 執行 `python3 gen.py out` 後，產生 `out/<W>x<H>-s<N>/`，例如 `out/120x40-s3/`。每個資料夾裡要有：
  - `screen.txt`：純文字，正好 H 列，每列的顯示寬度正好是 W。CJK 字和全形標點算 2 格。
  - `roles.json`：每一列是一個片段清單 `[[文字, 角色, 種類], ...]`，片段串起來要等於該列的文字。
    - 角色只能用 Claude Code 主題鍵：text、inactive、suggestion、success、warning、error、merged、permission、claude。不要用 subtle，它在淺色主題的對比不夠。
    - 種類填 `text` 或 `glyph`（框線、符號、小圖）。
  - `dark.ans`、`light.ans`：用 `brief/tools/cc-themes.json` 的 RGB 上色的 ANSI 檔。index 2 是深色、index 0 是淺色。gen3.py 已經有做法可以參考。
  - 有網址時加 `urls.json`：列出完整網址。
- 每一步加一行說明，寫在 `out/flow.json`：`[{"step":1,"title":"平常沒事","key_to_next":"…","next":2}, ...]`。

## 必過檢查（交件前自己先跑；沒過的會被退回）

`CC_THEMES=brief/tools/cc-themes.json python3 brief/tools/check3.py out`，結束碼要是 0。它檢查下面幾項：

- 逐列寬度等於 W。
- 框線左右邊同欄、上下角對齊。
- 可按的鍵（merged 角色）不出現在上半部（R1）。如果你推翻 R1，請在 NOTES.md 寫明；這一項仍會被標成 FAIL，交給 PM 判斷。
- 選項字母依序是 a、b、c…
- band（最下面那個框）裡不出現「背景」「卡住」「來源」「sha」。
- 深淺兩種主題的對比：文字 ≥ 4.5、符號 ≥ 3。
- 網址不能從中間斷開：放不下就整串移到下一行，或截短後加 `…`。
- 收合鍵 `[-]` 必須在框內。

渲染後，本席還會檢查：並排圖的直框線不可以有斷點（列距 15px）、不可以是空白圖。

## 範圍

- 只能寫你自己的資料夾 `doc/design/tri/<代號>/`。不要改 `brief/`，也不要改 repo 的其他地方。
- 這一輪只出設計稿，不寫實作碼。
- 卡片內容用假資料就可以，三張待決卡、一張「等你動手」卡；可以沿用 gen3.py 的資料。
