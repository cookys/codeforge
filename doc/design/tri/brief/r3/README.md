## 設計

1. **band 是底部操作熱區**。框在輸入框正上方，內容由上往下依序是：
   - 「等你動手」一行
   - 焦點卡的題目
   - 選項 a/b/c，建議的那個標 ★
   - s 送出
   - 下框：左邊按鍵提示，右邊分頁列

   R1：操作都靠近 prompt，資訊往上長。

   R7：band 只放問題、選項和建議；背景、卡住、來源都不在 band。
2. **右側 Pane 負責細節，只放文字、沒有按鈕**，跟著 band 的焦點卡走。內容有焦點卡的背景、卡住、來源，待決清單（哪張已選），以及「等你動手」的完整步驟。

   Pane 底部對齊 band 的上緣，往上長。上半部可按元件為 0（R1）。

   band 和 Pane 共用同一個焦點，按 p/n 會同時換張（R4）。
3. **分頁列只有一條，在 band 下框**，同時決定 Pane 顯示哪一頁。forge-stats 不再另開 pane，它的內容分到 Pane 的頁裡：
   - 「7 艦隊」：每個 agent 的 tok/s
   - 「5 花費」：用量和額度

   band 的狀態列保留 ϟ tok/s 小圖（R4）。
4. **選項鍵照字母對應**：a 一定是第一個選項（R6）。
5. **「等你動手」在 band 永遠只佔一行**，格式是「▲ 等你動手 N 張 · 第一張的標題 · 步驟在右側 Pane」：
   - 有 Pane（≥110 欄）時，完整步驟在 Pane。
   - 80 欄沒有 Pane，尾巴改成「v 看步驟」，按 v 才展開單卡版。
   - 選項永遠不會被這個區塊擠掉，所有尺寸都不用捲動就看得到全部選項，符合 01M89A37 的讓位規則。
   - 沒有 step 的卡不畫、也不計入張數。
6. **80 欄的退化**（照 v7.4 narrow）：
   - Pane 不開。
   - 選項後面的理由還留著。
   - 「m 附註」列省略，但 m 鍵還在。
   - 分頁列只寫目前那頁的名稱。
   - 按鍵提示縮短，多一個「v 細節」。

## 機械檢查（check3.py）

每張稿逐項檢查以下幾件事，任何一項不過，結束碼就是 1：
- **逐列寬度**：CJK 算 2 格，每列都要等於終端寬。
- **框線**：每個框的左右邊同欄、上下角都對得上。
- **R1**：可按的鍵（merged 色）不出現在上半部。
- **R6**：選項字母依序是 a、b、c。
- **R7**：band 框裡不出現背景、卡住、來源、sha。
- **深淺主題對比**：對 Claude Code 內建主題的實際 RGB 計算，文字要 ≥ 4.5，符號和框線要 ≥ 3。
- **網址不斷行**（PM 01M89CD1-1）：畫面上的每段網址都要是完整網址，或是完整網址的開頭加上「…」。
- **[-] 在框內**（PM 01M89CD1-2）：收合鍵要落在某個框的上下左右邊界之內。

反例有兩份，兩份的結束碼都是 1：
- neg/80x24 故意做錯：寬度多 1 格、上半部放了可按的鍵、用 subtle 色寫字、[-] 在框外。
- neg2/120x40 是上一版稿：網址從中間斷 1 處，[-] 有 2 處在框外。

並排圖另外用 shotcheck.py 檢查：
- 最多的那種顏色超過 99% 就判定是空白圖。
- 每段直框線（同一欄從 ╭ 到 ╰）在圖上要連續，中間不能出現背景色像素。

五張都過，列距是 15px，等於字格高度。反例是改之前 22px 行距的圖，最大斷點 6px，判定 FAIL。

## 這一版改了什麼（PM 01M89CD1、01M89CGV）

- 網址不再從中間斷。放不下一行時整串移到下一行；一行還放不下就截短，尾端加「…」，Pane 底部寫「y 複製完整網址」。
- [-] 收合鍵移進框內：Pane 和 band 都放在上框線右側。狀態列只留 ▾。
- 斷行規則：
  - 以子句（，。；：）為單位。
  - 子句放不下時在空白處斷，空白之間的字串不拆。
  - 最後一行不會只剩一兩個字。
- 並排圖的列距原本被 1.7em 撐到大約 22px，改成等於字格高度（15px），直框線恢復連成一條。這是 build.py 的修正（fix/grid-pitch），19103 偏離頁也一起套用。
