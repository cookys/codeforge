# Console 完整設計：計畫（單 01M89Q2Z）

## 0. 目標與限制
- **目標**：操作員看一次就能把整個 console 定案，不用再一句一句叫 codeforge 改。
- **範圍**：底列 9 個分頁，每頁畫完整狀態。
- **骨架不動**：v2 版面（74f24a9，含 a58153b 修正）是固定骨架，不准推翻：
  - 左下是 index
  - 右下是回覆區
  - 右上是來龍去脈，由下往上長
  - 對話區在左上，不能被蓋到
- **照舊的裁定**：
  - 可按的鍵只在底部（R1）
  - 不做 u 收回
  - 選項鍵照字母對應
  - 送出前寫「送出後不能改」
  - 底列合併狀態與分頁
- **衝突怎麼處理**：裁定有衝突時寫進處置表交 PM 裁，不自己改操作員定的版面。
- **不做**：實作。這張單只出設計稿，資料以 autopilot@23fd23038 的 `mods/live` 為準。

## 6. 異質引擎審查（ADR-0001）
- **審查席**：codex 與 agy 兩家。這條線不是私有線，grok 和 fable 是候補。
- **每一輪規則**：
  - 審查席讀指定 sha 的 worktree。
  - 稿子第一行寫 sha，每條意見附步號或 file:line；沒讀 repo 的稿不收。
  - 每條意見標 blocking 或 note。blocking 要寫出可以重現的情境：在哪一步、哪個尺寸，看到什麼錯。
- **第 0 輪**：審計畫和盤點表。檢查盤點表的 file:line 對不對、有沒有漏功能、狀態矩陣有沒有漏。
- **第 1 輪到第 3 輪**：審畫面。blocking 全部修完才進下一輪；到第 3 輪還沒解的交 PM 裁。
- **留檔**：每一輪的審稿原文放 `review/r<N>-<engine>.md`，處置表放 `review/r<N>-dispositions.md`，欄位是意見、處置（修／不修附理由／交 PM）、修在哪個 sha。
