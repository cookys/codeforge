## 1. 盤點表
見 `INVENTORY.md`。它由三份分頁盤點合併而成（`inv-1-3.md`、`inv-4-6.md`、`inv-7-9.md`），本席抽查過 file:line。每個功能寫明四件事：
- 資料來源
- 操作員要做的決定
- 按鍵
- 五種狀態的現況

## 2. 骨架怎麼套到 9 頁
v2 的三塊骨架原本只為待決頁設計。其他頁沿用同一個骨架，三塊的用途對照如下：

| 塊 | 待決頁（v2） | 其他頁的通則 |
|---|---|---|
| 左下 index | 全部卡 | 這頁的條目清單（派工的每一輪、審查的每一席、殘留的每一項、艦隊的每個 agent、待辦的每一列）；▸ 是目前這一筆 |
| 右下回覆區 | 問題、選項、送出 | 目前這一筆「要你做的事」和可按的鍵。沒有要做的事時只放一列摘要，鍵列只剩換頁和換筆 |
| 右上來龍去脈 | 卡的來源、前因、背景、卡住 | 目前這一筆的細節：log 尾、file:line、時間線、來源指令。只放文字，不放鍵 |

- 沒有條目清單的頁（1 現況、9 說明），index 改放這頁各段的目錄，用來跳段。
- 每頁實際怎麼套，以盤點表為準，寫在 §3。

## 3. 每頁的畫面清單（盤點後填）
每頁都畫下列狀態：

| 代號 | 狀態 | 畫法 |
|---|---|---|
| N | 平常 | 有資料，3–5 筆 |
| E | 空的 | 沒有資料，寫明「為什麼空」和「什麼時候會有」 |
| M | 很多筆 | 超過 index 高度：捲動位置、上下還有幾筆 |
| L | 內容很長 | 來龍去脈超過可用高度時看全文的做法（v2 沒畫的第 1 件） |
| X | 出錯或讀不到 | 指令失敗或檔案不存在：寫出哪個來源壞了，舊資料留著還是清掉 |
| S | 資料過時 | 超過新鮮度門檻：時間戳記和過時標記 |

跨頁情況：
- **C1**：開著卡時切到別頁再切回來，草稿和焦點都要保留。
- **C2**：開著卡時把右欄切到艦隊頁（v2 沒畫的第 2 件）。
- **C3**：卡多到 index 要捲動（v2 沒畫的第 3 件，屬於待決頁的 M 狀態）。

每頁的步號表、按鍵到下一步的對應，由 gen.py 輸出到 `out/flow.json`。

## 4. 產出格式
- **產生器**：`doc/design/tri/console/gen.py`，從 v2 的 gen.py 延伸，共用片段模型與框線函式。
- **輸出路徑**：`out/<tab>-<state>/<W>x<H>/{screen.txt,roles.json,dark.ans,light.ans}`，以及 `out/flow.json`。

- **80x24 的做法**：照 v2。index 縮成回覆框的第一列，來龍去脈疊在回覆框上方。
