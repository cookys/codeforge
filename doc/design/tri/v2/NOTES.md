# v2：左下 index、右下回覆區、右上來龍去脈

產生：`PYTHONDONTWRITEBYTECODE=1 python3 gen.py out`（10 步 × 209x49／120x40／80x24，深淺兩色）。
檢查：`CC_THEMES=doc/design/tri/brief/tools/cc-themes.json python3 doc/design/tri/brief/tools/check3.py doc/design/tri/v2/out`，結束碼 0。

每張畫面的第 1 列是「設計稿註記」（第幾步、按什麼鍵到哪一步），不是 UI 的一部分；其餘都是實際畫面。

## v2 版面：照操作員要求改了什麼

操作員看完合併稿（29a1b1c）說：「操作這樣不太對，bottom-left 可以是 index，bottom-right 是回復區，然後右邊往上漲的是來龍去脈」。v2 照這句話重排，寬螢幕（≥110 欄）長這樣：

```
  對話區                                  ╭─ 2 待決 · 第 3 張的來龍去脈 ──────╮
                                          │ 來源 …  背景 …  卡住 …            │
                                          ╰─ 只能看 · 跟著下面那張卡換 ───────╯
╭─ 要你處理 4 張 · 已選 2 ──┬─ 第 3 張 · 預覽先拍幾欄 ───────────── [-] ─╮
│ 待決 3 張                 │ ▸ 問題                                      │
│  ✓ 1 合併 plan    a 合併  │     a: …  b: …  ★ 建議  c: …                │
│ ▸· 3 預覽先拍幾欄 未選    │ s: 送出已選 2 張 · 送出後不能改             │
╰─ p/n 換張 ────────────────┴─ a/b/c 選 · m 附註 · s 送出 · Esc ─────────╯
 ● 進行中 │ 待決 3 ▲ 1 │ …                 1 現況  2 待決 … 9 說明 ▾
```

**和合併稿的差別：**

| 東西 | 合併稿 | v2 |
|---|---|---|
| 全部卡的清單 | 右欄 Pane，一張兩列 | **左下 index**，和回覆區同一個底部框，一張一列 |
| 目前這張卡 | 整個 band | **右下回覆區**：問題、動手步驟、選項、★ 建議、m 附註、s 送出 |
| 背景、來源、前因 | 按 v 才接在清單下面 | **右上來龍去脈**，常駐，跟著選中的卡換 |
| v 鍵 | 開關細節 | **沒有了** |
| 右欄的框 | 清單＋細節，有「v 看細節」提示 | 只有文字，沒有任何鍵，連收合鍵 `[-]` 都不放 |
| 下框的按鍵提示 | 一整條 | 分兩段：`p/n 換張` 在 index 下面，其餘在回覆區下面 |

由我判斷的四件事：

1. **index 和回覆區合成一個框**，中間一條直線。兩格講的是同一件事（哪一張、怎麼答），p/n 一按兩格一起變；分成兩個框會多兩條邊，120 欄的回覆區會少 4 格。
2. **來龍去脈是另一個框**，貼右邊、底邊貼著回覆框的上邊，由下往上長，高度就是內容的列數（第 1 張 2 列、第 3 張 4 列、第 4 張 13 列）。它在對話區的右邊，不佔對話區的任何一列；寬度固定（120 欄是 52、209 欄是 78），對話區至少留 67 欄。
3. **來龍去脈裡的順序是時間順**：來源 → 前因 → 背景 → 卡住。最上面最舊，「卡住」貼著回覆區。這樣放不下時從最上面收，留下來的是離決定最近的那幾列。
4. **「等你動手」卡的編號步驟放在回覆區**，不放來龍去脈。理由：步驟是要做的事，不是前因；步驟裡的網址要用 `y` 複製，可按的鍵只能在底部（R1）；而且「先照 1、2 做，再選」和選項要在同一眼裡。

右欄和分頁的關係：來龍去脈就是 Pane 的「2 待決」頁（標題寫 `2 待決 · 第 N 張的來龍去脈`），所以 band 和 Pane 還是同一套、forge-stats 還是併在同一個 Pane。開著卡時按 7，右欄換成艦隊頁，按 2 換回來龍去脈；這個組合沒有畫。

**80x24 的做法：index 縮成一列，來龍去脈疊在回覆框正上方。**

- 80 欄放不下左右兩格：回覆區的選項列最長 65 格（動手卡的網址列 73 格），再放 34 格的 index 就要截掉網址或選項的理由。所以 index 縮成回覆框裡的第一列（佇列條：`✓1：a  ▸·2 外掛更新時機  ·3  ▲4`），每張卡一格，仍然看得到已選哪個字母、未選、▲ 要動手和目前這張。
- 來龍去脈也放不下右欄，改成獨立的框疊在回覆框正上方，一樣由下往上長、跟著卡換、只有文字。
- 80x24 只有 24 列，所以來龍去脈有上限：**對話區至少留 3 列**。超過上限時從最上面收起，第一列寫「⋯ 更早的 N 列收起來了」。步驟 6、7 的 80x24 就是這個樣子（13 列收成 3 列，留下最近一筆前因、背景、卡住）。
- 沒有選「index 留左格、來龍去脈拿掉」：操作員要的是來龍去脈常駐，而且 v 鍵已經拿掉，80 欄不能變成看不到。

**題目六步對到的步號：** ① 平常沒事 = 1；② 有待決卡要選 = 3；③ 等你動手卡 = 6；④ 看一張卡的細節 = 4（來龍去脈跟著換張；內容變長看 5，很長看 6）；⑤ 艦隊頁或其他頁 = 9（另一頁是 10）；⑥ 送出後的回饋 = 8（送出前是 7）。依題目順序：`[1,3,6,4,9,8]`。

**照舊不變的：** 可按的鍵只在底部（R1，30 張全過）；沒有 u 收回；a 是第一個選項；最底下一行合併狀態和分頁；m 附註有寫才出現（步驟 7）；送出列在按 s 之前寫「送出後不能改」（步驟 3–7 每一張都有）。

**要回報的一件事：check3 的選項字母檢查在寬螢幕沒有真的檢查到。** 它用「去掉行首的 `│` 和空白後，是不是以 `a:` 開頭」來找選項列。v2 寬螢幕的選項列左邊是 index 的字，所以找不到任何選項列，這一項是空過（`R6_letters` 是 `[]`）。80x24 的選項列在行首，照常檢查到 `[a,b,c]`。寬螢幕另外由 gen.py 自己保證：`reply_rows` 裡有一行 assert，選項字母不是 a、b、c 就不產生。建議 check3 之後改成在整列裡找 `a:`。

band 檢查（最下面的框不出現「背景」「卡住」「來源」「sha」）沒有衝突：來龍去脈是另一個框，回覆框裡沒有這些字。

## 設計理念

操作員說「不知道怎樣改」，我的判斷是畫面上同時有太多地方在講同一件事。v2 每個位置只做一件事，而且位置不動：

1. **左下 index：哪一張。** 待決卡和「等你動手」卡在同一份清單，分兩段。一張一列：`✓ 1 合併 plan  a 合併`、`· 3 預覽先拍幾欄  未選`、`▲ 4 時冶 PL02 定案  要動手`，目前這張前面有 `▸`。
2. **右下回覆區：怎麼答。** 只放目前這張。待決卡和「等你動手」卡同一個形狀，後者多兩列編號步驟。按 a/b/c 就打勾並自動跳到下一張沒選的；全部選完，送出列變色，按 s 一次送出。
3. **右上來龍去脈：為什麼問。** 只有文字。不用按任何鍵，換張就跟著換。
4. **最底下一行：整體狀態和分頁。** 永遠在、永遠同一個位置。沒事時就只有這一行。

眼睛的路線是固定的：左下看到哪一張，往右答，想知道為什麼就往上看。

## 和第三輪最大的三個不同

1. **三塊各有固定位置。** 第三輪的 Pane 同時放細節、清單、動手步驟三段。這一版清單在左下、答覆在右下、前因後果在右上，每塊只有一種內容。
2. **「等你動手」不再是另一個區塊。** 第三輪是 band 頂端固定一行「▲ 等你動手 1 張」，步驟放在 Pane，沒畫做完之後怎麼回覆。這一版它是 index 裡的第 4 張卡，步驟和回覆選項都在回覆區，三種寬度都看得到完整網址。
3. **分頁列固定在最底下那一行，並且畫出完整流程。** 第三輪分頁列嵌在 band 下框線右側，band 收起就沒有地方放；也只畫了待決一個狀態。這一版 10 步在三種寬度都畫出來，每步標了按鍵。

## 推翻了哪些裁定

題目列的六條裁定都沒有推翻：操作區在下方（R1 項 30 張全過）、band 和 Pane 一套、forge-stats 併進 Pane、120x40 不捲動看得到全部選項、a 是第一個選項、少字。

「少字：第一眼只看到問題、選項和建議」要說明一句：來龍去脈現在常駐，字比合併稿多。這是操作員這次自己要的；它在另一個框、另一個位置，回覆區本身仍然只有問題、選項、建議。

偏離 v7.4／第三輪／合併稿的做法：

| 偏離 | 理由 |
|---|---|
| v7.4 S3 三張卡同頁攤開 → 回覆區一次一張，全部卡在 index | 三張攤開要 20 列以上，80x24 放不下；一次一張才能保證任何寬度選項都不捲動。 |
| v7.4 分頁列在框下獨立一列（第三輪在下框線）→ 併進最底下的狀態行 | 沒有卡時框不存在，分頁列就沒有家；併進底線後位置永遠固定。 |
| 第三輪「m 附註：（空）」常駐一列 → 有寫才出現 | 空的附註列是字，不是資訊（R7）。m 鍵仍列在下框提示。 |
| 合併稿的 v 鍵和「細節接在清單下面」→ 拿掉，改成來龍去脈常駐 | 操作員 v2 要求。 |
| 合併稿清單一張兩列（第二列是問題）→ index 一張一列 | index 只有 34 格，問題放不下；目前這張的問題就在右邊回覆區。代價見自評。 |

## 自評缺點

- **其他卡的問題要換過去才看得到。** index 只有卡名和狀態；合併稿的清單有每張卡的問題，v2 沒有。
- **來龍去脈很長時沒有地方看全文。** 80x24 從上面收起後只說收了幾列，這一稿沒有畫捲動或展開的方法（右欄不放鍵）。建議實作時讓「2 待決」頁在收起回覆框後顯示全文，要另外畫。
- **回覆框的高度會跟著卡變。** 寬螢幕一般卡 6 列，動手卡 7 列，寫了附註 8 列；換張時選項的列位置會差 2 列。可以固定成 8 列，代價是平常多兩列空白。
- **209 欄的回覆區很空。** 選項最長 65 格，回覆區有 168 格；沒有為了填滿而加字。
- **寬螢幕選卡時右欄一定會開**，120x40 佔 52 欄。按 `[-]` 收起整組。
- **卡很多時 index 要捲。** 寬螢幕 index 的列數等於回覆區的列數（6–8 列），放得下 4–6 張；更多張時要以目前這張為中心捲動，沒有畫。80 欄的佇列條放得下大約 8 張（只剩編號）。
- **寬窄兩種長相不同**：寬螢幕 index 是直的清單，80 欄是橫的一列；來龍去脈一個在右、一個在上。
- **80x24 的動手卡畫面很滿**：回覆框 10–11 列、來龍去脈 5 列，對話區只剩 3 列（含註記列）。
- **開著卡時把右欄切到別頁（例如 7 艦隊）的畫面沒有畫**；80 欄這個組合放不下艦隊頁 10 列，要另外決定。
- **送出後不能改。** 沒有收回，按錯 s 只能另外找 PM；只靠送出列的一句「送出後不能改」提醒，沒有二次確認。
- **80 欄時底線的分頁只剩數字**（只有目前頁有名字）。
- **選了自動跳下一張**對習慣先看完再選的人可能太快；按 p 可以回頭。
- **步驟 7 是兩個動作合成一張**：按 a 之後又按 m 寫了附註，流程表裡只標了 a。
- 第 1 列的設計稿註記佔掉一列對話區，實作時不存在。
